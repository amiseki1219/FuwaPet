# 絶対に守ってほしいルール  【固定】

## 1. git の状態は一切変えない

以下は **すべて禁止**です。

```
git add / commit / push / pull / fetch --prune / merge / rebase
git branch（作成・削除・切替）/ checkout / switch
git reset / restore / stash
git clean          ← 特に git clean -fd は絶対に実行しない
```

**コミットと push は Fork を使って私が手動でやります。**
AI は「コミット文」と「対象ファイルの一覧」を提案するところまでです。

状態を見るだけの操作（`status` / `log` / `diff` / `show` / `ls-files`）は、
必ず `--no-optional-locks` を付けて実行してください。

```bash
git --no-optional-locks status
```

理由：`--no-optional-locks` を付けないと `.git/index.lock` が残ってしまい、
Fork 側で `fatal: Unable to create '.git/index.lock'` が出て作業できなくなります。
（過去に実際に起きました。しかも Linux 側からは `rm` できないので、私が手で消すことになります）

### ★ git を見るときの落とし穴（日本語ファイル名の NFD）

Mac のフォルダを Linux 側から見ると、**日本語ファイル名の濁点が分解（NFD）されて別名に見えます。**

```
git のインデックス  : ソファ　デフォルト      ← 「デ」は1文字（NFC）
Linux から見た実体  : ソファ　テ゛フォルト    ← 「テ」+「゛」で2文字（NFD）
```

このせいで、**コミット済みのファイルが「未追跡」に見えます。**
実際に2回、AI が「リポジトリに穴が空いています」と誤報告しました。

**対策：日本語名のファイルについて「未追跡です」と報告しないでください。**
正しいのは私の Fork の表示です。判断に迷ったら「Fork ではどう見えていますか？」と聞いてください。

### ① スロットのキーは「カテゴリ ＋ 番号」（`SlotKey`）

1カテゴリに複数スロットを持たせるための仕組みです。

```
かべA = SlotKey(Decoration2, 0)  → セーブ文字列 "Decoration2"
かべB = SlotKey(Decoration2, 1)  → セーブ文字列 "Decoration2#1"
```

0番はカテゴリ名だけの文字列にしてあるので、**この機能を入れる前のセーブデータもそのまま読めます。**
`FurnitureCategory` から `SlotKey` への暗黙変換があるので、
スロットが1つしかないカテゴリは今までどおり `Apply(FurnitureCategory.Bed, id)` と書けます。

### ② enum に新しいカテゴリを足すときは必ず「末尾」に

```csharp
public enum FurnitureCategory
{
    Bed, Table, Sofa, WallShelf, Shelf, Window,
    Nightstand, RoomLight, Decoration, Rug, RoomShell,
    Decoration2,   // ← 新しいものはここに足す
}
```

セーブデータは文字列なので並べ替えても平気ですが、
**`.asset`（カタログ）と `.unity`（シーン）の中では category が「数値」で保存されています。**
途中に挿入すると、既存の全行が1つずつズレて別カテゴリになります。

### ③ アイテムのプールはカテゴリ単位で1つ

同じカテゴリの複数スロットは**同じ一覧を共有**します。
カタログの行をスロットごとに2重に作る必要はありません。
同じ時計をかべAとかべBの両方に飾ることもできます（意図した仕様です）。

### ④ 「なし」の表し方

カタログの行に `isEmptySlot` というチェックがあります。

- チェック ON ＋ Prefab 空 → 「なし」。選ぶとスロットが空になり、**家具の下の接地影も自動で消えます**
- チェック OFF ＋ Prefab 空 → **設定ミス扱い**。エラーログを出して何も変更しません

「Prefab を入れ忘れた」と「意図的に空」を区別するための仕組みです。

# 過去にハマったこと（同じ地雷を踏まないために）  【固定＋追記】

## Unity まわり

**`SaveManager` がシーンに無い**
RoomEdit から直接 Play すると、ぴよこを選んでいるのに Poko が出て、部屋を編集しても保存されない。
`SaveManager` は DontDestroyOnLoad のシングルトンなので、そのシーンから起動する場合は
シーン内に存在している必要があります。

**キャラの Root は `WalkSystem`。`PokoWalkRoot` ではない**
ぽこは `PokoWalkRoot` の中、他の4キャラは `CharacterDisplayAnchor` の中に生成されます。
両方の親である `WalkSystem` を指定しないと、全キャラを隠せません。
（`CharacterStaticDisplayController.cs` が `characterId == "poko"` だけ別扱いしているため）

**キャラの消え方**
縮小や上昇のアニメーションは「気持ち悪い」と不評でした。
**その場でぱっと `SetActive(false)` で消す**のが正解です。演出を足さないでください。

**スロットには歪んだスケールが入っている**
`FurnitureSlot_Nightstand` は `(2.5, 3, 2.5)`、`FurnitureSlot_Bed` は `(2, 2, 2)` です。
- 光の演出などをスロットの子にすると潰れます。位置だけ合わせてください
- **スロットの Scale が 2 なら、中の Prefab の Position も2倍されて効きます。**
  Prefab の Position を 0.5 動かすと、部屋の中では 1.0 動きます

**アイテム一覧のボタンが見切れる**
Viewport のサイズ、ItemButton の高さ（240）、SelectFrame のサイズ（187.8×276.9）の
組み合わせで簡単に見切れます。Scroll View の高さは 280 以上必要です。

**Unity 内のファイル移動は必ず Project ウィンドウ上で**
Finder で動かすと `.meta` が元の場所に取り残され、GUID が変わって参照が全部切れます。
（Prefab を作る前なら実害はありませんが、作った後だと作り直しになります）

## 3Dモデル・テクスチャまわり

**Tripo の FBX はテクスチャが「別フォルダ」で出てくる**
FBX の中には `tripo_convert_xxxx.fbm/Color.jpg` という**相対パス**で参照が入っています。
**FBX と同じ階層にその名前のフォルダが無いと、色が出ません。**
ダウンロードしたフォルダごと Unity に入れるのが正解です。
`.fbm` フォルダの名前は**絶対に変えないでください。**

**テクスチャのインポート設定が Sprite になる**
このプロジェクトでは、FBX 付属のテクスチャが `Texture Type = Sprite` で入ります。
特に `Normal.jpg` がそのままだと**法線マップとして一切機能せず、凹凸が消えます。**

| テクスチャ | 正しい設定 |
|---|---|
| `Color.jpg` | Default / sRGB ON |
| `Normal.jpg` | **Normal Map** |
| `*_metallic.JPEG` | Default / **sRGB OFF** |
| `*_roughness.JPEG` | Default / **sRGB OFF** |

Project ウィンドウで検索して複数選択すれば一括変更できます。

**Unity の自動生成マテリアルは metallic / roughness を繋がない**
Base Map（Color）と Normal Map しか繋がりません。
URP Lit は metallic と smoothness を1枚にまとめた形を要求するため、
Tripo の「別ファイル2枚」形式は自動対応できないからです。
Blender での見え方と差が出るのは主にこれが原因です。**Blender を経由しても改善しません。**

**キャラ別 Prefab は RoomShell 方式で作る**
`Furniture_RoomShell_Poko.prefab` が手本です。中身は
「FBX への参照 ＋ Transform の上書き」だけで、メッシュやマテリアルの差し替えがありません。
FBX をシーンに置いて位置を合わせ、Prefab として保存するだけで作れます。

**キャラ別 Prefab は Position と Rotation を5体そろえる**
Sofa と Nightstand は5体とも同じ Position / Rotation で、**Scale だけキャラごとに違います。**
これが正解のパターンです。
Bed で「える と ここ だけ複製時の初期値のまま」にしていたら、
部屋の反対側（X が 2.4 ズレ）に出て「とっ散らかって」見えました。

**Prefab 方式によって回転補正の要否が変わる**
- メッシュ直参照の古い方式（`Furniture_*_Default`）→ Z-up がそのまま入るので **X −90°** が必要
- FBX への PrefabInstance 方式（RoomShell 系）→ Unity が Y-up に変換済みなので **回転補正は不要**

```csharp
    b.button.onClick.AddListener(() => OpenItemList(b.category));

// ○ ローカルにコピーしてから渡す
foreach (var b in categories) {
    var cat = b.category;
    b.button.onClick.AddListener(() => OpenItemList(cat));
}
```

**`JsonUtility` はコンストラクタを呼ばない**
フィールド初期化子（`= new List<...>()`）が走らないので、
その項目が無い古いセーブデータを読むとリストが `null` のままになります。
読み込み側で必ず null チェックしてください。

**カタログの Prefab 欄が空だと切り替えられなくなる**
`Apply()` が LogError を出して**何もせずに抜ける**ため、
一度「なし」にすると他の家具に戻せなくなります。
「なし」の行は必ず `isEmptySlot` にチェックを入れてください。

**状態によって変わるものは「判断を1箇所に集約する」**
カメラとキャラの表示は、カテゴリ選択中 / 編集中 / プレビュー中 の3状態で変わります。
呼び出し側で個別に `MoveCameraTo` / `MoveCameraHome` を書いていたら、
**プレビューを抜けるときだけ戻し忘れる**バグが出ました。
`UpdateCameraForState()` のように状態から決めるメソッドに寄せてください。
